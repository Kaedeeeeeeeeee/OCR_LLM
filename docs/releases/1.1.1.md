# Cheese! OCR 1.1.1 (7)

## Changes

Recover from specific Apple Vision model failures by restarting a sandboxed OCR
helper and retrying once. Keep warmed models for normal captures, enforce bounded
timeouts outside the recognition process, and show recognition progress.

See [the investigation](../ocr-reliability.md) for evidence, regression results,
and limitations. Localized App Store release notes are in
[1.1.1-notes.json](1.1.1-notes.json).

## Validation

- Nine regression tests passed, including 23 actual OCR recognitions across five
  languages and 20 successive crash/recovery cycles.
- The user confirmed the installed fix works in actual use.
- Universal Release archive built for arm64 and x86_64.
- Exported Mac App Store package passed deep/strict code signature verification.
- Embedded helper has exactly the two sandbox inheritance entitlements, and no
  Debug fault-injection switches in its Release binary.

## Reproduce the archive

From the repository root:

```sh
xcodebuild -project QuickOCRLLM/QuickOCRLLM.xcodeproj \
  -scheme QuickOCRLLM -configuration Release \
  -destination 'generic/platform=macOS' \
  -derivedDataPath .derivedData/OCRRelease \
  -archivePath .derivedData/AppStore/1.1.1/CheeseOCR.xcarchive archive
```

Export with `method=app-store-connect`, `destination=export`,
`manageAppVersionAndBuildNumber=false`, and the team's current distribution
certificate, Mac installer certificate, and provisioning profile for
`com.cheeseocr.app`. The inherited helper does not need its own profile.

On the release machine, resolved export options and logs are saved under
`.derivedData/AppStore/1.1.1/`. The old Xcode-managed profile did not include the
current distribution certificate, so a new `Cheese OCR Mac App Store 2026`
profile was created without revoking existing certificates or profiles. Xcode's
installer certificate selector did not resolve the installed certificate; its
explicit SHA-1 identity was used instead.
